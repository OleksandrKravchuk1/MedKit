# Специфікація MVP

## Модель даних

- `medicines`: id, name, form (tablets | capsules | syrup | drops | ointment | spray | other),
  dosage?, barcode? (unique), notes?, createdAt
- `packages`: id, medicineId (FK → medicines, cascade), expiryDate (TEXT 'YYYY-MM-DD'),
  quantity (int, default 1), batch?, status (active | used | discarded), notificationId?, createdAt
- `tags`: id, name (unique), color
- `medicine_tags`: medicineId, tagId (складений PK, cascade)
- `settings`: key, value. Дефолти: remindDaysBefore = 7, notifyTime = "10:00"

Один препарат має кілька упаковок з різними датами; сповіщення прив'язане до упаковки.
Сід при першому запуску, теги: Біль, Температура, Застуда, Алергія, Шлунок, Перша допомога.

## Екрани

```
src/app/
  _layout.tsx            # Stack; міграції, сід, обробник тапу по сповіщенню
  (tabs)/_layout.tsx     # Tabs: Ліки | Налаштування
  (tabs)/index.tsx       # список
  (tabs)/settings.tsx
  medicine/new.tsx
  medicine/[id].tsx      # деталі
  medicine/[id]/edit.tsx # та сама форма, що й new
  scanner.tsx            # presentation: 'modal'
  onboarding.tsx
```

Кореневого `src/app/index.tsx` бути НЕ повинно: він конфліктує з `(tabs)/index.tsx`.

1. **Список**: пошук за назвою; горизонтальні чіпи-теги (мультивибір); картки з назвою, формою,
   найближчою датою активних упаковок і кількістю упаковок. Статус кольором:
   зелений > 30 днів, жовтий ≤ 30, червоний = прострочено. Сортування за найближчою датою.
   FAB «+». Порожній стан.
2. **Форма (new/edit)**: назва з автодоповненням з наявних medicines, форма, дозування, теги,
   дата придатності (date picker; якщо відомі лише місяць і рік, береться останній день місяця),
   кількість, нотатка, кнопка сканера. Валідація zod.
3. **Сканер**: модальна камера з рамкою; запит дозволу; захист від повторного спрацювання.
   Повертає результат у форму:
   - EAN-13/EAN-8: пошук `medicines.barcode`; якщо знайдено, підставити препарат,
     інакше зберегти код для нового запису.
   - GS1 DataMatrix: парсити AI (01) GTIN, (17) expiry YYMMDD (DD = 00 → останній день місяця),
     (10) batch, (21) serial; враховувати роздільник GS (\x1D) і можливий префікс `]d2`.
     Парсер у `src/lib/gs1.ts`, покрити unit-тестами (jest-expo).
4. **Деталі**: дані препарату, список упаковок; дії «використав», «викинув», «додати упаковку»,
   редагувати, видалити (з підтвердженням).
5. **Налаштування**: за скільки днів нагадувати, час сповіщення, CRUD тегів.
   Зміна налаштувань → перепланування всіх сповіщень.
6. **Онбординг**: 1–2 екрани; запит дозволу на сповіщення з поясненням. Показується один раз
   (прапорець у settings).

## Сповіщення (`src/lib/notifications.ts`)

- schedule / cancel / rescheduleAll.
- Тригер: (expiryDate − remindDaysBefore) о notifyTime. Якщо ця дата вже минула, а упаковка
  ще не прострочена, сплануй на завтра о notifyTime.
- notificationId зберігати в packages; скасовувати при зміні дати, статусі used/discarded і видаленні.
- Ліміт iOS 64 заплановані сповіщення: планувати лише найближчі 60.
- Тап по сповіщенню відкриває `medicine/[id]`.
- Android: створити notification channel.

## Етапи (після кожного: зупинка і звіт)

1. Видалити `src/app/index.tsx`. Встановити залежності, налаштувати Drizzle (`drizzle.config.ts`,
   babel/metro для імпорту .sql-міграцій), схема, перша міграція, сід, запуск міграцій у `_layout`.
2. Список + форма + деталі: повний CRUD без сканера і сповіщень.
3. Сповіщення + налаштування + онбординг.
4. Сканер + GS1-парсер із тестами.
5. Полірування: порожні стани, обробка помилок, tsc і lint чисті.
